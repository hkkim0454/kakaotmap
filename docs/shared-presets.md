# 공용 목적지 1·2

## 사용

검색한 장소를 선택한 뒤 검색창 위의 목적지 1 또는 2 카드에서 ‘선택한 장소 저장’을 누릅니다. 누구나 저장·변경·삭제할 수 있으며 비밀번호를 요구하지 않습니다. 저장된 카드를 누르면 기존 지도·내비·링크 공유 기능을 사용합니다. 기존 카카오 JavaScript 키 편집 잠금은 유지됩니다.

Firestore 프로젝트 `svt-led-calculator`의 기본 데이터베이스에 `barogil_presets/1`, `barogil_presets/2`만 사용합니다. 문서는 name/address/x/y만 저장합니다. 웹 설정의 공개 API 키를 사용하며 Analytics·로그인·서비스 계정 키는 사용하지 않습니다.

## Firebase 콘솔에서 한 번 적용

Firestore → 규칙에서 `public/firestore-presets.rules.txt` 내용을 붙여 넣고 게시합니다. 이 파일은 사용자가 제공한 기존 만료 규칙을 그대로 두고, 두 목적지 문서에만 읽기·쓰기·삭제 권한을 추가합니다. LED 계산기의 기존 권한이나 데이터는 변경하지 않습니다. 기존 전역 규칙은 2026-08-07에 만료된 상태이며 이 변경으로 LED 계산기의 만료된 접근이 복구되지는 않습니다.

기존 규칙이 제공된 내용과 달라졌다면 전체를 교체하지 말고 `match /barogil_presets/{slot}` 블록만 기존 documents 블록 안에 추가합니다. 문서 3번, 추가 필드, 범위를 벗어난 좌표는 허용하지 않습니다. 컬렉션 전체 조회 권한은 열지 않고 두 문서를 개별 조회합니다.

## 동기화와 실패 처리

첫 접속, 창으로 복귀, 수동 새로고침, 화면이 보이는 동안 60초 간격으로 두 문서를 읽습니다. 개인 브라우저 저장으로 대체하지 않습니다. 오프라인·권한 오류 때 성공 안내를 표시하지 않으며 재조회 전 편집을 막습니다. 화면에서 읽은 updateTime을 쓰기·삭제 조건으로 보내 동시 수정 시 다른 사람이 바꾼 문서를 덮어쓰지 않습니다. 저장 완료 전 중복 클릭을 막고, 기존 장소 덮어쓰기와 삭제 시 확인합니다.

## 검증

`npm test`: 두 클라이언트의 공유 저장·삭제, 빈 슬롯, 권한 오류, 동시 변경 충돌, 잘못된 입력, UI 선택·취소·실패, 기존 공유·내비·설정 잠금 회귀 테스트. 실제 규칙 게시 이후 두 브라우저에서 저장 → 새로고침 → 삭제를 확인해야 합니다. 로컬 환경에 Firestore Emulator가 없어 보안 규칙의 에뮬레이터 검증은 수행하지 않았습니다.
