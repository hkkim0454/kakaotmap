# 모임 날짜와 지난 모임 자동 정리

## 의도

'모임 열기' 목록에 이미 끝난 모임이 쌓이지 않게 한다. 날짜를 넣은 모임은 날짜가 지나면 저절로 목록에서 빠지고, 그 밖의 모임은 삭제 버튼으로 직접 지운다. 링크를 받은 사람들의 목록도 같은 기준으로 정리된다.

## 목표

- 모임 만들기/편집 화면에 선택 입력인 **모임 날짜**(`YYYY-MM-DD`)를 추가한다.
- 날짜는 링크의 모임 데이터에 `date` 필드로 들어간다. 날짜가 없는 기존 v1 링크는 그대로 유효하다.
- 목록 각 줄에 날짜를 표시한다. 예: `11/28(토) · 천룡CC 금요일 모임 · 천룡CC`.
- 한국 시간 기준으로 모임 날짜 다음 날 0시부터 그 모임을 목록에서 제거하고 localStorage에서도 지운다. 작성 중인 초안은 제거하지 않는다.
- 지난 모임 링크를 열면 목적지는 보여 주지만 목록에는 다시 추가하지 않는다.
- 휴대폰에서 편집/삭제 버튼이 보이도록 한 레이아웃 수정(`d6c8e09`)을 함께 배포한다.

## 하지 않는 것

- 지난 링크 자체를 막지 않는다. 링크에 데이터가 들어 있어서 완전히 막을 수 없다.
- 시간(시:분)은 받지 않는다. 날짜 단위로만 판단한다.
- 서버에 모임 목록을 저장하지 않는다.

## 제약

- 짧은 링크 Worker의 `validSharedUrl`은 모임 키를 `v,name,places`로 제한한다. `date`(형식 `YYYY-MM-DD`, 실제 존재하는 날짜)를 허용하도록 `worker/route-api.mjs`와 `public/route-worker.txt`를 함께 고친다. Worker 배포는 사용자가 `wrangler deploy`로 직접 한다.
- 테스트는 `node --test`로 실행하며 외부 의존성을 추가하지 않는다.

## 접근 방식

| 방식 | 장점 | 단점 |
|---|---|---|
| **링크에 날짜 포함 (선택)** | 받은 사람 목록도 함께 정리, 날짜를 한 번만 입력 | Worker 수정과 재배포 필요 |
| 날짜를 내 브라우저에만 저장 | 서버 수정 불필요 | 받은 사람 목록은 정리되지 않음 |
| 날짜가 지나면 링크 차단 | 링크가 확실히 무효화된 것처럼 보임 | 데이터가 URL에 있어 실제로 막을 수 없음 |

사용자가 지난 모임을 목록에서 치우는 것을 원했고 링크를 여러 사람에게 보내므로, 링크에 날짜를 넣는 방식을 선택했다.

## 구현자에게 맡기는 부분

- 날짜 판정 함수(오늘 한국 날짜 계산, 지남 여부)의 위치와 이름.
- 목록 정렬은 기존 최근 사용 순서를 유지한다(구현자 판단으로 변경하지 않음).
- 날짜 입력은 `<input type="date">`를 사용한다.
